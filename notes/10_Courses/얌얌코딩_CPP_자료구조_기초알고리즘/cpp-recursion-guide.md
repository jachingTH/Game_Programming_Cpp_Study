## 재귀의 구성

재귀 호출마다 새 호출 상태가 생기고, 그 호출이 끝나면 호출한 위치 다음 줄부터 실행을 이어갑니다. 코드를 복사하는 것이 아니라 각 호출의 매개변수·지역 상태가 분리된 호출 흐름으로 이해합니다.

| 요소 | 역할 |
| --- | --- |
| 종료 조건 | 더 이상 호출하지 않을 깊이 또는 답을 처리할 시점 |
| 상태 변화 | 다음 호출이 종료 조건으로 가까워지게 하는 인자·경로 변화 |
| 호출 전 코드 | 깊이 들어갈 때 실행 |
| 호출 후 코드 | 하위 호출이 끝난 뒤 복귀하며 실행 |

종료 조건이나 상태 변화가 없으면 호출이 계속 쌓여 스택 한계에 도달할 수 있습니다. 정확한 한계 크기는 환경마다 다릅니다.

## 분기와 경로 기록

한 호출에서 여러 선택지를 재귀 호출하면 호출 구조는 트리처럼 분기합니다. 선택 배열 `path[level]`에 값을 기록하고, 하위 호출 뒤 원래 상태로 되돌리는 흐름이 백트래킹입니다.

```cpp
path[level] = choice;
dfs(level + 1);
path[level] = 0;
```

`visited`도 같은 방식입니다. 호출 전에 true로 표시하고 복귀 직후 false로 되돌려야 다른 경로가 독립적으로 탐색됩니다.

## 가지치기

답이 될 수 없는 경로는 일찍 건너뛰면 호출 수를 줄일 수 있습니다. 단순 조건은 호출 전 `continue`, 여러 상태를 함께 검사할 때는 함수 진입 후 `return`이 읽기 쉬울 수 있습니다. 어느 방식이든 조건은 "현재 선택"을 검사하는 위치에 맞아야 합니다.

예를 들어 연속 중복을 금지하려면 현재 `path[level]`에 후보를 넣은 뒤 `path[level] == path[level - 1]`을 검사하거나, 후보와 이전 선택을 비교한 뒤 호출을 건너뜁니다. 이전 두 칸만 비교하면 현재 후보의 중복을 막지 못합니다.
